## The problem

A prediction game is a problem of **timing and trust**. If a user can submit a prediction
after kickoff, the game is pointless. If two members of the same group see different
standings, so is it.

On top of that, the application is bilingual. And bilingual applications have a classic blind
spot: error messages. The interface gets translated carefully, and then the server returns
`"Cannot delete: record has children"` in English to a user who chose Spanish.

## Architecture decisions

### The server sends codes, the client writes the sentence

Every repository and unit-of-work operation returns `ActionResponse<T>` with `WasSuccess`,
`Message` and `Result`. But `Message` does not carry a sentence. It carries a **code**
(`ERR001` … `ERR018`).

The frontend translates that code against its `.resx` resource files. The consequence is that
the message language depends on who reads it, not on who produced it, and adding a language
never requires touching the backend.

### Generics with escape hatches

The backend uses the same chain as `Orders` (controller, unit of work and repository,
generic at each level), so a new CRUD entity only writes what differs from the default
behaviour.

Concrete controllers override what they need and add `full` variants accepting DTOs instead
of entities, for the cases where the API model and the database model stop matching.

### Cascade deletes are off deliberately

`DataContext.OnModelCreating` sets `DeleteBehavior.Restrict` **globally**. Deleting a record
with children does not drag half the database with it: it returns `ERR002`.

That is a deliberate choice about which kind of failure is preferable. In a game chaining
tournaments, teams, matches and predictions, an accidental cascade is silent data loss; an
explicit error is only an inconvenience.

### Data scope is not something the client gets asked about

Pagination travels in a `PaginationDTO` with `Page`, `RecordsNumber`, `Filter`, `Id` and
`Email`. When an endpoint must scope data to the calling user, the controller sets
`pagination.Email = User.Identity!.Name` **server-side**, ignoring whatever arrived in the
request.

A client cannot request someone else's data by changing a parameter.

## Outcome

An administrator maintains the catalogs: countries, teams, tournaments, participating teams
and the match fixture. Any registered user creates a private group, which makes them its
admin and generates a six-character invitation code, also shareable as a URL.

Members submit a score prediction for each match, predictions lock before kickoff, and once
real results are entered the points feed the group standings.

The SPA is Blazor WebAssembly with MudBlazor, dark mode by default, and Spanish and English
resource files.
